# Project Rules

These rules apply to the entire project unless explicitly changed.

------------------------------------------------------------------------

## 1. Project Goal

This is a production-inspired resume project built to demonstrate
backend engineering skills with Spring Boot.

Every major implementation should be something that can be confidently
explained in an internship interview.

------------------------------------------------------------------------

## 2. AI Usage

AI is used to accelerate development, not replace understanding.

Workflow:

Understand → Generate → Read → Modify → Explain

Never merge code that is not understood.

Primary tools: - Cursor - ChatGPT - Other free AI tools when appropriate

------------------------------------------------------------------------

## 3. Code Quality

-   Follow clean architecture and layered design.
-   Avoid unnecessary complexity.
-   Keep methods and classes focused.
-   Use meaningful names.
-   Prefer readability over cleverness.

------------------------------------------------------------------------

## 4. Learning Rule

Before using a new framework feature or annotation, understand:

-   What it does
-   Why it is needed
-   Alternatives
-   When not to use it

------------------------------------------------------------------------

## 5. Documentation

Documentation evolves with the code.

Major design decisions must be documented before or during
implementation.

------------------------------------------------------------------------

## 6. Git

Commit after completing meaningful milestones.

Commit messages should clearly describe the change.

------------------------------------------------------------------------

## 7. Technology Constraints

Prefer free and open-source technologies.

Current stack:

-   Java
-   Spring Boot
-   Maven
-   PostgreSQL
-   Spring Data JPA
-   Hibernate
-   Spring Security
-   JWT
-   Flyway
-   React + Vite
-   Tailwind CSS
-   Local file storage during development

Paid services should be avoided unless no practical free alternative
exists.

------------------------------------------------------------------------

## 8. Production Mindset

Build as if real users could use the application.

Include: - Validation - Exception handling - Logging - Testing -
Documentation - Security

------------------------------------------------------------------------

## 9. Interview Readiness

Every major file, class, API, and architectural decision should be
explainable.

If the implementation cannot be explained, it is not complete.

------------------------------------------------------------------------

## 10. Decision Rule

When multiple approaches exist:

1.  Simplicity
2.  Maintainability
3.  Scalability
4.  Learning value

Choose the solution that best satisfies these priorities.

------------------------------------------------------------------------

## Mission

Build something that is technically solid, enjoyable to develop,
deployable, and worthy of being one of the strongest projects on the
resume.
